# 416MES 仓储管理系统（单机离线版）

单页应用：`index.html` 双击即用，无需安装、无需联网（需与 `mes-core.js` 等同目录文件一起拷贝）。适配汉印 N41 热敏打印机 + 60×40mm 三防标签纸。

> 注意：「排版工具」页签依赖 `typesetting/` 文件夹和 `nec-gallery.js`（NEC 图库清单）；库存规则依赖 `mes-core.js`；摄像头扫码依赖 `jsqr.min.js`。拷贝本系统时请整目录复制。

## 快速开始

1. 门户首页 `home.html`（双击或访问 http://localhost:8000/home.html ）：五个模块入口 + InvenTree 集成入口 + 在线状态自检
2. 作业端 `index.html` 双击即用（同目录需有 `mes-core.js` / `jsqr.min.js` / `nec-gallery.js`），无需安装、无需联网
3. 首次打开自动载入种子数据：64 个货架库位码（B区 2货架×4层×8位）+ 12 个工位格码 + 40 个容器码 + 2 条示例物料
4. 「标签打印」页勾选 → 预览 → 打印（纸张可选 **60×40 标签纸** 或 **A4 整版** 3×7=21 张/页；色彩可选 **高对比纯黑 / 彩色主视觉**；属性文字 **自动占满空白**（8.5–18pt 自适应），编码自动填满左栏，字号 70%–120% 可微调）
5. 定期点「导出备份 JSON」（全量含流水）或「导出 Excel 台账」备份（数据存在浏览器 localStorage，换浏览器/清缓存会丢）

## 开发命令

```bash
npm install          # 安装依赖（仅 xlsx）
npm run dev          # 启动真源服务（静态页 + /api/feishu/* 代理），http://localhost:8000
npm run serve:static # 无飞书配置时只想开静态页：scripts/static-server.mjs
npm run check        # 全量脚本语法检查（node --check）
npm test             # 语法检查 + 核心库存规则单元测试
```

`npm run dev` 在缺少 `feishu-backend.config.json` 时自动降级为纯静态服务（页面顶部显示「⚪ 离线模式 · 本机数据」），不会因为没配密钥而启动失败。

### 核心库存规则（mes-core.js）

`mes-core.js` 是库存数字的唯一权威来源，页面只调用不重复实现：

- **`applyStockChange()`** — 库存数量的**唯一写入口**：改数量与写流水在同一函数内完成，二者不可分离；默认拒绝把库存改成负数。
- **`recordTransaction()`** — 流水的**唯一写入口**：只追加、`seq` 单调递增、`balance` 记录写入后的真实库存。
- **`normalizeItems()` / `createOrder()`** — 工单创建时校验物料存在性，并把**同一物料多行自动合并**为一行（数量相加）。
- **`validateExecution()` / `executeOrder()`** — 执行前把明细**按物料汇总后再校验库存**，因此「同一物料多行、合计超库存」会被拦截，不会扣成负库存；`item.qty` 保留**计划数量**，实际执行数量记在 `order.execQty` 与 `order.execBatches`。
- **`parseStocktakeInput()` / `applyStocktake()`** — 盘点输入严格校验，空值 / 非数字 / 负数一律拒绝，**绝不静默转 0**（显式输入 `0` 表示确认无货，合法）。
- **`replayAudit()`** — 从首条余量反推期初、逐条重算链式余量，定位篡改或丢数；兼容无 `seq` 的旧数据。
- **`recordScan()` / `locateMaterial()`** — 结构化记录每次扫码；查不到台账时回查最近一次**带位置**的扫码、最近一条流水、最近一张相关工单，拼出「最近位置 + 最近时间」线索（30S 定位）。
- **`orderProgress()` / `orderSummary()`** — 工单的计划 / 已执行 / 剩余数量与进度；计划数量取 `item.qty`，已执行取 `execQty` 累计。
- **`executeOrder()`（部分执行）** — 可多次调用；每次数量不得超过**剩余计划数量**，传 `0` 表示本次跳过该物料；执行完 → 已执行，只做了一部分 → 部分执行。
- **`cancelOrder()` / `reverseOrder()`** — 未执行的工单可直接取消（不动库存）；已执行过的必须先**冲销**（把已执行数量按原方向反向写回库存，再置为已取消）。冲销同样走 `applyStockChange`，所以库存与流水始终成对，回放校验不会断链。
- **`orderTransactions()` / `orderHistory()`** — 关联流水（按 `ref` 匹配）与完整历史（创建 → 各执行批次 → 取消/冲销）。

改任何库存相关逻辑时，请先改 `mes-core.js` 并补 `test/mes-core.test.js`，再让 `index.html` 调用。

浏览器里确认（`http://localhost:8000/index.html`）：
1. 顶部状态应为 **🟢 飞书真源已连接**；断网/关掉服务后应变成 **⚪ 离线模式 · 本机数据**
2. 在台账页改一个物料库存 → 到飞书多维表刷新，该物料「库存数量」应已变化，且「库存流水」多一条

4. 断网时改库存 → 顶部出现 **☁️ 离线队列 N 条**；恢复网络后刷新页面，队列应自动冲刷并消失

### 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `⚪ 离线模式`，`ping` 返回 `feishu:false` | 缺 `feishu-backend.config.json` | 放到项目根目录（已被 .gitignore 排除，需单独拷贝） |
| `❌ 读取表 ... 失败` | `lark-cli` 未登录 / token 过期 / 应用未加入该 Base / 表 ID 不匹配 | 重新 `lark-cli config`，或核对配置里的 8 个表 ID |
| `❌ 找不到 lark-cli` | PATH 里没有 | 安装后确认 `lark-cli --help` 可用 |
| 页面一直绿但数据不更新 | 早期版本的缺陷（已修复） | 升级到 `043fc20` 之后；`/api/feishu/state` 读取失败现在会返回 502 并显示离线 |

> ⚠️ 读取失败**绝不能**被当成「飞书表是空的」。历史版本曾把 `lark-cli` 报错静默转成空表，导致页面误报 🟢「已连接」——如果你在旧版本上验证过飞书同步，建议在修复版本上重跑一次 `status` 与 `pull`。

## 库存工单管理（Phase 3）

「库存工单」页签把工单从「创建 + 扫码执行」两段式升级为完整管理模块：

| 能力 | 说明 |
|---|---|
| 工单列表 | 工单号 / 类型 / 日期 / 状态 / 进度条 / 执行批次 / 详情入口，新的在前 |
| 搜索与筛选 | 按工单号、物料码、物料名搜索；按状态（待执行/部分执行/已执行/已取消）与类型（LL/BH/JH/TL）筛选；顶部统计各类张数 |
| 状态模型 | 待执行 → 部分执行 → 已执行；未执行可直接**取消**，已执行过须**冲销**后关闭 |
| 部分执行 | 扫码页数量框预填**剩余数量**，改成更小的值即分批执行，填 `0` 跳过该物料；可多次执行直到计划数量用完 |
| 详情页 | 计划数量 / 实际数量 / 剩余数量三列对照 + 明细分物料表 + 执行历史（创建/每次批次/取消/冲销）+ 关联库存流水 |
| 取消 | 仅限未执行任何数量的工单，记录时间/操作人/原因，**不改动库存、不写流水** |
| 冲销 | 已执行（含部分执行）的工单把已执行数量按原方向回退到库存，写入「冲销」流水，保留执行历史便于追溯 |

数据口径：`item.qty` 永远是**计划数量**且不被执行改写；实际执行数量累计在 `order.execQty`；每次执行的明细记入 `order.execBatches`。历史数据里「未执行」与「待执行」等价（飞书/Excel 单选项仍是「未执行」）。

## 扫码闭环（Phase 2）

扫码页支持 7 种前缀，无前缀时自动识别（工单码 → NEC 工单码 → 物品码 → 手册码 → 物料码）：

| 扫码串 | 查到什么 |
|---|---|
| `MAT:GJ-SD-001` | 物料：名称/规格/成本/库存（含低库存与负库存告警）+ 库位/容器/模块区 + 最近扫码·流水·工单 |
| `LOC:B-01-01-01` | 库位：说明 + 存放物料清单（含合计库存） |
| `LOC:M-01` | 模块区：该区物料清单 |
| `CTN:XK-001` | 容器：存放物料清单 |
| `WIP:LL20260915001` | 工单：明细/执行数量/执行后库存，可直接执行扣减或增加 |
| `NEC:NEC-0001` | NEC 小工单：标题/类型/负责人/状态/物料，并联动台账显示相关物料库存 |
| `ITM:WP-001` | 物品（设备/工具/展品）：名称/规格/库位 |
| `MAN:SC-001` | 手册：名称/版本/库位 |

**30S 定位兜底**：扫 `MAT:` 未命中（台账里没有这个编码）时，系统回查该编码的扫码历史、库存流水与相关工单，在结果里直接给出「上次扫码时的库位/容器/模块区 + 最近扫码时间 + 最近流水 + 最近工单」。位置线索取**最近一次带位置的扫码记录**，所以后续未命中的重复扫码不会把线索冲掉。

### 双向同步闭环（feishu-sync.mjs）

```bash
node feishu-sync.mjs status                        # 连通性 + 各表记录数
node feishu-sync.mjs push 416MES_备份_xxx.json     # 本地备份 → 飞书（按编码 upsert：已存在更新、不存在新建，幂等）
node feishu-sync.mjs pull [输出.json]              # 飞书 → 本地备份 JSON（网页端「导入合并」回本机）
```

- **上云**：网页端「导出备份 JSON」→ `push` —— 8 张表全量按业务键（物料码/库位码/容器码/编号/物品码/手册码/工单号/流水号）去重，重复推送不产生重复记录
- **回本**：`pull` 生成与网页端「导入合并」完全兼容的备份 JSON（select 单选 / datetime 时区 / 明细串均已按本地格式归一化），合并按编码去重、流水取最大序号
- 库存流水只增不改：无 seq 的旧数据跳过不推，云端流水号 `#000123` 幂等
- 已验证完整往返：导出 → push → pull → 导入合并，日期/时间戳/余量逐字节一致

### 网页端云端实时同步（/api/feishu-sync）

- 网页工具栏「☁️ 云端同步」：直接从飞书后端拉全量数据并合并（人员主数据以云为准、同编号覆盖）；线上环境打开页面时也会自动静默同步一次
- 实现：Vercel Serverless Function `api/feishu-sync.js`，tenant_access_token 读取 8 张表，输出与「导出备份 JSON」同构数据，与「导入合并」共用同一套合并逻辑
- 配置：Vercel 环境变量 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`（应用需 base:record:read 权限且已加入 Base）；本地双击 file:// 使用时自动改走线上接口 https://mes.newenergycoder.club/api/feishu-sync（CORS 已放行）

## 模块区大卡（A4 整页，NEC 主视觉）

模块区是正式主数据（与库位码同台账、随 Excel 导出/导入、可删可增）：内置 M-01 连接器 / M-02 电机 / M-03 电池 / M-04 防护设备 / M-05 端子线材。新增：「编码生成」页填名称点「生成模块区」自动编 M-xx；删除：「标签打印 → 模块区卡」勾选后「从台账删除勾选」。打印：类型条选 **模块区卡**（自动切 A4 模式）→ 全选 → 打印，每页一张大卡（Just Scan QR 风格，机读串 `LOC:M-0x`，扫码页直接识读）。

物料大类建议：GJ 工具、HC 耗材、PJ 配件、DZ 电子件——中类自定，流水 3 位。

## 打印操作（汉印 N41）

1. 装 60×40mm 三防热敏纸，用驱动自带工具校准纸张
2. 在「标签打印」页勾选记录，点「🖨 打印勾选标签」
3. 打印对话框：**纸张 60×40mm（自定义）、边距=无、缩放=100%、取消页眉页脚、背景图形=开**（色条需要）
4. 二维码内容=带前缀机读串，手机/扫码枪均可扫

## 扫码出入库闭环（规则 5）

在「扫码出入库」页用扫码枪或手输，回车确认：

- `MAT:GJ-SD-001` → 查物料库存/位置
- `LOC:B-01-03-04` / `CTN:XK-001` → 查该位置存放什么
- `WIP:LL20260909007` → 打开领料工单，确认数量后「确认执行」**扣减**库存
- `WIP:BH…` / `WIP:TL…` → 执行后**增加**库存；库存不足或未建档会拦截
- 工单执行一次后闭环，不可重复执行；**没有扫码动作，库存数就不变**

## 维护规则

1. **编码不变，属性可变**：改名/换规格/调货位只改台账字段，编码永不重打；标签只在物理载体报废时作废
2. **台账即主数据**：「导出 Excel」得到 4 个 sheet（物料台账/库位/容器/工单记录），可直接导入飞书多维表格，也可编辑后「导入 Excel」回系统
3. **空位提前批量打印**：「编码生成」页按货架/层/位参数一键补齐，贴上即启用
4. **打印登记**：每张标签右下角自动带打印日期；三防纸正常用 2 年以上，褪色即重打，扫码核对编码一致
5. **工单闭环**：工单打印随货走，扫 `WIP:` 码执行才动库存

## 场地与分类体系

| 场地码 | 场地 | 存放定位 |

**位置码（三级）**：货架场地 `YH-01-03-04`（场地-架-层-位）；开放空地 `K401-A03`（场地-通道-块位，地贴/立柱贴码）。「编码生成」页场地码下拉含 TQ/YH/K401/B，支持块位码批量生成。
